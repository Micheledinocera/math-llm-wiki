# Math LLM-Wiki

A system for writing mathematics articles with an LLM. Claude Code maintains a wiki of definitions, results and examples. For each statement it tracks where it comes from, what it depends on and how far it is proved. The author keeps the mathematical judgment, and articles draw only on what the wiki records as usable.

Status: **v0.1**. The rules are a first hypothesis to test on two case studies in combinatorics. The design, in Italian, is in [docs/spec-v0.1.md](docs/spec-v0.1.md).

## Origins

- **LLM Wiki** by Andrej Karpathy (April 2026): immutable raw sources, a Markdown wiki written and maintained by the LLM, and a schema file with the rules.
- **Lean blueprints** ([leanblueprint](https://github.com/PatrickMassot/leanblueprint) by Patrick Massot): every result has a status, and the results form a dependency graph.

This project differs from the original pattern in four ways:

- the raw layer is split into external sources and personal ideas, which carry different weight;
- every statement has an epistemic status and a mandatory provenance;
- articles form their own layer, separate from the wiki;
- the lint checks the drafts as well as the wiki.

## How it works

```text
raw/sources/  --/ingest-->  wiki/  --/draft-->  articles/
raw/ideas/    --/compile-->   |
                           /query (read-only)   /lint (wiki + articles)
```

| Status | Meaning | Usable in an article |
| --- | --- | --- |
| `conjecture` | believed true, no proof | only as a declared conjecture |
| `sketch` | proof idea with missing steps | no |
| `proposed` | complete proof written by the agent, not checked | no |
| `partial` | partly checked by the author | yes, with a warning |
| `verified` | checked by the author | yes |
| `cited` | proved in a source, with a precise reference | yes; warning if the source is a preprint or informal |
| `refuted` | false, with a counterexample | no |

Only the author can set `partial` and `verified`. A result's status can never be stronger than the status of its weakest dependency. Sources also have a `reliability` level: `standard`, `refereed`, `preprint` or `informal`.

The full rules are in [CLAUDE.md](CLAUDE.md).

## Usage

You need [Claude Code](https://claude.com/claude-code) and Python 3.10 or later. [Obsidian](https://obsidian.md) is optional: open the repository as a vault to browse the wiki and follow the `[[slug]]` links.

1. Put a source in `raw/sources/<firstauthor><year>.md`, as Markdown (convert PDFs first), then run `/ingest raw/sources/<id>.md`.
2. Write an idea in `raw/ideas/YYYY-MM-DD-title.md`, then run `/compile raw/ideas/<file>`.
3. Ask questions with `/query <question>`.
4. Start an article with `/draft <slug>`: first the plan, then the draft, one section at a time.
5. Check everything with `/lint`, or with `python scripts/lint.py` for the mechanical checks only.
6. When you have checked a proof yourself, set the result's `status` to `verified`, or to `partial` with its `unchecked_steps`.

Each operation ends with a summary and an entry in `log/changelog.md`. The agent does not commit: review the diff and commit yourself.

## Layout

```text
CLAUDE.md          rules for the agent
docs/              design specification
raw/sources/       external sources (immutable) and _registry.md
raw/ideas/         personal ideas, dated
wiki/              index, notation, open questions, and definitions/, results/, examples/, concepts/, sources/
articles/<slug>/   plan.md, draft.md, build/ (generated by the planned /export)
templates/         page templates
log/changelog.md   operation log and the list of proofs ready for verification
scripts/lint.py    mechanical checks
.claude/skills/    /ingest, /compile, /query, /draft, /lint
```
